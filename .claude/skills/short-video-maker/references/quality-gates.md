# 品質ゲート — 閾値と検収手順

ショート動画の出荷判定はこのファイルが正。**機械で測れるものは機械が判定し、耳と目の判定だけを人間に残す。**

## TTS音声の自動検収(経路B・工程1-Bで必ず実装する)

生成した音声に対して機械判定する。判定はffprobe/ffmpeg・波形解析で行う。

| 検査 | 判定基準(目安) | 意味 |
|---|---|---|
| 短すぎ | 実測秒数 < 想定秒数(文字数×0.18秒程度)の50% | 一部しか読まれていない |
| 尻切れ | 末尾60msのピーク > 0.05 | 文の途中で切れている(自然な終端は減衰する) |
| 音割れ | ピークが1.0(フルスケール)に張り付き | クリッピング |
| 無音 | 全体RMSが極端に低い | 生成失敗 |
| **数字の誤読** | whisper書き起こしと台本の**数字リストが完全一致** | 「4億→8億」級の事故検出。ショートは数字がフックなので1桁の誤読が致命傷 |

- ASR照合は表記ゆれを正規化してから(漢数字⇄算用数字・ひらがな⇄漢字)。忘れると正しい音声が延々と不合格になる
  - **かな数詞も正規化対象(実測)**: 誤読対策で台本を「ひとつ目」「じゅうなな年」とかな書きすると、ASRは「1つ目」「17年」と算用で書くため、素朴な数字照合が偽の不一致を出す。asr_qc.pyはかな数詞→算用の変換を**数字照合・全文照合の両方に**実装済み(「ご」「し」等の同音多義は変換しない・助数詞が続く場合だけ変換)
  - **⚠️かな数詞語の読みの白黒はテキストでは付かない(構造的限界・実測)**: 「みっつめ」をASRが「3つ目」と書き戻すため、単独切り出しASRでも「みっつめ」と正しく読んだか「さんつめ」寄りに崩れたかは判別できない。**かな数詞を含む行は耳検収の注目リストに必ず入れる**
- 疑い区間はffmpegで切り出し、**0.75倍速にしてから再ASR**する(等速ASRの誤聴とTTSの実誤読を区別できる)
  - **⚠️切り出しの2大罠(実測・ゲート自体が壊れる)**: ①**m4a/aacから直接-ssで切ると位置が数百msズレる**ことがあり(編集リスト・プライミングの影響)、1秒未満の単独クリップが別区間の音になって誤判定する→**必ず一度WAVに全展開してから切る**(asr_qc.pyは実装済み)。②**-ssを-iの後ろに置いて-filter:a atempoと同居させると、シークがフィルタ後のタイムラインに適用されて÷0.75の位置を切ってしまう**→切り出しと減速は別コマンドに分ける(切ってからatempo)。切り出しがズレていると、whisperは短いクリップにもっともらしい幻聴を返すので、ズレに気づきにくい
- **⚠️ASRゲートの盲点(実測)**: whisperは言語モデルなので、文脈から復元できる複合語の誤読を**正しい表記に自動補正して書き起こす**(実例:「体言止め」を「からだごんどめ」と誤読していても、文中では「体言止め」と書き戻されて素通しする)。対策=音訓の読みが揺れうる複合語(体言止め・意志力など、訓読み+音読みの混成語)は、**word timestampsで対象語だけを切り出し、文脈なしの単独クリップで再ASR**する。単独なら補正が効かず実際の音が出る(実測:「体ごん止め」「意識力」と露呈した)。それでも不安な語は先回りでかな置換してよい(この場合のみ例外)。**最後の砦は人間の耳**——機械検収を全部通っても、出荷前の通し試聴は省略しない
- **⚠️さらに深い盲点=同字異読(実測)**: 誤読が**同じ漢字の別の正しい読み**のとき(実例:「疑問形」を「ぎもん**かたち**」と読んだ)、単独切り出しASRでも書き起こしは「疑問形」になり**機械では原理的に検出できない**(表記が変わらないため)。この型を捕まえられるのは人間の耳だけ。予防=読みが複数ある接尾漢字(形=けい/かたち・方=ほう/かた・生=せい/なま 等)の音読み複合語は、**台本側で混成表記にして読みを固定**する(「疑問けい」。全かな化は分解読みの副作用があるので接尾だけかなにする)。**既知の読み事故は assets/script_lint.py が執筆段階で機械検出する**(「開いた」=あいた/ひらいた の実誤読を受けて常設。同字異読約60語=ブロック+実誤読実績語=警告の2層辞書。TTSに渡す前に必ず通し、耳検収・ASRゲートで新種を見つけたらHETERONYMS/MISREADS辞書に追記して育てる)
- **⚠️連濁の脱落も実誤読の型(実測)**: 複合語の連濁(「ネット断ち」=ねっと**だ**ち)が清音「たち」で読まれる。これは単独切り出しASRで露呈する(「ネットたち」と書かれる)ので機械検出可能。対処=連濁に頼る複合語は音読み熟語に言い換える(「ネット断ち」→「ネット遮断」)。また、使用頻度の低い熟語は頭の子音ごと化けることがある(実例:「無一文」→「**ぶ**いちぶん」)→日常語への言い換え(「貯金ゼロ」)が安全
- **⚠️ポーズ内クリック=舌打ち様ノイズ(実測・本人の耳で発覚)**: TTSは読点ポーズの真ん中に短い口腔ノイズを吐くことがある(実測: 立ち上がり3ms・ピーク0.28・減衰の尻尾つき。静寂の中なので小さくてもはっきり聞こえる)。数字・誤読・尻切れのゲートでは原理的にかからないので**専用の機械検査を常設する**。検出=1msエンベロープで「本体>0.05の塊を尻尾>0.015までヒステリシス拡張し、塊が80ms未満かつ前後±80msの環境が<0.022」(尻尾を本体に含めないと『前後が静かでない』と誤判定して取り逃す=実測)。発話中の破裂音は前後が鳴っているので誤検出しない。除去=**該当区間のゼロ化+4msコサインフェード**が正(尺不変でcue時刻が無傷・ポーズ内なので発話に触らない。セグメント再生成は尺が変わり誤読ガチャも引き直しになるので不利)。**実装済みツール=assets/declick_pauses.py(scan/fix)**・ASR照合一式=assets/asr_qc.py
- 不良は設定を変えて自動リトライ最大3回。3回失敗した文は**言い回しごと変える**(何度引いても直らない語は語が悪い)
- 合格後、**EQ明瞭化→loudnorm(I=-16目安)**の順で仕上げる(EQチェーンと掟はSKILL.md工程1-B手順5。声トラック限定・適用1回・順序厳守)
  - **⚠️loudnormの後にdeclick_pauses.pyをもう一度scanする(実測)**: TTS直後のscanが白でも、loudnormのゲイン増幅で閾値未満だったクリックが新たに閾値超えになって出現する。**ゲイン処理(loudnorm・音量調整)をかけるたびに再scanが必須**

## 切り抜き音声の検収(経路A)

- [ ] カット点にプツ音がない(afade極短が入っているか)
- [ ] 全編通して無音化していない(ffmpegの `-ss/-to` を `-i` の後ろに置いた事故の典型症状)
- [ ] 文が途中で切れていない(カット点は必ず文末)
- [ ] フックと本編の間に意図した無音gapがある

## 口パク・キャラの検収(最初の1本で必ずキャリブレーション)

- [ ] 無音区間で口が開かない / 発話中に口が閉じっぱなしにならない(閾値を素材の実測RMSに合わせる)
- [ ] 瞬き・にっこり目のとき白目や瞳が透けない(瞼パッチのズレ。character.jsonの目座標を再計測)
- [ ] 頷きで首から上だけが動く(頭と胴の分解ミスだと全身が回る)
- [ ] ポーズ差分の切替時に腕が二重に見えない(胴体は常に1枚だけ表示)
- [ ] キャラの接地影が足元にある(浮いて見えたらdisplayHeightと影位置の不整合)

## セーフゾーンの検収(縦動画の必修・静止画QCで確認)

1080x1920に対して、プラットフォームUIが被る帯がある。**数値は目安なので、最初の1本は必ず実機のプレビューで確認する**(UIはアプリ更新で変わる)。

| 帯 | 目安 | 被るもの |
|---|---|---|
| 下部 約350px | y > 1570 | キャプション・音源表記・進行バー |
| 右側 約140px | x > 940 | いいね・コメント・シェアの縦アイコン列 |
| 上部 約220px | y < 220 | 検索・ライブ等のヘッダ |

- [ ] 字幕ゾーンが下部帯に入っていない(テンプレートの bottom 430 はこのための値。下げるな)
- [ ] フックのでか文字が上部帯・右側帯に食い込んでいない
- [ ] **でか文字カードの折り返し**: 1行8文字を超えるタイポは自動折り返しで最後の1文字が孤立する(実測)。長文は`\n`で改行位置を明示し、それでも収まらなければ`textPos:'middle'`(小さめ文字)にするか文言を刈り込む
- [ ] AI開示の小表記は下部帯内でもよい(常時表示が目的。ただし完全に隠れる位置は不可)
- [ ] **でか文字カード(typo)のbg指定漏れがない**(機械検査: `grep -n "type: 'typo'" src/cues/*.ts | grep -v "bg:"` のヒット0を確認。未指定は安全網でmonoに落ちるが、素材の意味で明示するのが正: 断言=shu/速度=mono/告白・文化=washi)。**⚠️このgrepは「1オブジェクト=1行」の書式が前提**(実測: 可読性重視でオブジェクトを複数行に整形すると検査がすり抜ける)。cues/scenesはcues.sample.tsと同じ1行書式で書くこと
- [ ] **表情がにこにこ一辺倒になっていない**(機械検査: 台本にシリアス・苦い話の語(見過ごせない/赤字/失敗/損/怒り/悲しい/辛い等)があるのに `grep -cE "mood: '(stern|sad|serious)'" src/cues/<name>.ts` が0なら要修正)。smile/laughの山とstern/sadの谷を1本の中に両方置く——笑顔しかない動画は、シリアスな行で表情と内容がチグハグになる(実例: 「家族は見過ごせない」をにこにこ顔で話していて違和感の指摘を受けた)
- [ ] **カード明けに前の字幕が蘇っていない**: 全画面カード(typo/フックカード)の終了時刻より次のcue開始が遅いと、隙間の数フレームだけカード前の古い字幕が全不透明で再表示される(実測・3フレームで目視可能)。テンプレートは`liveCue`(カード開始をまたいだcueを死んだ扱いにする)で根治済み——CharacterShort.tsxの字幕描画を改造するときはこの安全網を外さない。QC静止画はカード明け直後+1フレームも1枚撮る

## 動画ファイルの機械検収(レンダ後)

- [ ] 解像度1080x1920・H.264・AAC・fps指定どおり(ffprobeで確認)
- [ ] 実測秒数 = 音声実測秒数±0.5秒(durationInFramesの計算ミス検出)
- [ ] ファイル末尾まで再生できる(尻切れエンコードなし)
- [ ] 音量: ラウドネスが配信基準(I=-16前後)にそろっている

## リーガル・開示検品(公開前に毎回)

- [ ] **効果・利益の断定表現がない**: 「稼げる」「必ず儲かる」「誰でも成果」等は景品表示法・各種業法の規制対象になりうる。**発話・字幕・キャプションの三点セットで検査**する
- [ ] NG表現が見つかったら**音声ごと言い換えて再生成**する。字幕とキャプションだけ直して音声に残すのは検査逃れであり禁止
- [ ] AI音声の開示: 動画内小表記(`aiVoiceLabel`)+プラットフォームのAI生成ラベルの両方
- [ ] AI生成画像・映像を含む場合も同様にプラットフォームの開示設定を確認
- [ ] 実在の人物・企業への言及は事実確認済みのものだけ(出典を残す)
- [ ] 他人の声のクローンでない(本人の声か書面許諾のみ)

## 出荷前・総合検収12項目

1. フック(最初の1秒)が音・文字・画の三点同時に立ち上がる
2. 全編を通しで再生して音ズレ・字幕ズレが体感0.5秒以内
3. 数字の読み上げが台本と完全一致(機械検算済み)
4. カット点にプツ音・白飛び事故がない
5. 字幕・でか文字がセーフゾーンに収まっている
6. 生成画像内の日本語に誤字・嘘の字がない(拡大目視。生成画像は「それっぽい嘘の字」を混ぜる)
7. 意図しない顔・人物が映っていない(生成Bロールは画面内のスマホやTVにも顔が出る)
8. 口パク・瞬きが破綻していない(QC静止画+通し再生)
9. AI開示表記が動画内にある(AI音声・AI画像利用時)
10. 効果・利益の断定表現がない(発話・字幕・キャプションの三点)
11. **参照音声・APIキー・voice_idが共有物に混ざっていない**(フォルダを全ファイル列挙して確認)
12. cuesファイル・台本の正本がバックアップされている
