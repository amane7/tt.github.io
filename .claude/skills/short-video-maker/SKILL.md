# short-video-maker — AIでショート動画を作る

このスキルは、実運用中のショート動画工場の型を、自分のキャラ・自分の声・自分のブランドに差し替えて使える形にしたものです。

**前提: このスキルはFableクラス(最上位モデル)での実行を想定しています。**
長い工程の自走・機械検収の実装・Remotionプロジェクトのセットアップが必要なため、下位モデルでは品質が保証できません。下位モデルで実行している場合は、最初にユーザーへその旨を伝えてください。

**環境の前提**: Node.js(Remotionを使う)・ffmpeg・whisper。すべてClaudeがセットアップを自走してよい。Remotionは企業規模によって有償ライセンスが必要になるソース公開ソフトウェアなので、**商用利用の前に必ず公式サイトの最新ライセンス条件をユーザーと一緒に確認する**(個人・小規模はおおむね無料枠だが、条件は変わりうる)。

## 思想(判断に迷ったらここへ戻る)

- **撮影しない。データから組み立てる。** 直しのコストを「文章の直し」と同じにする
- **勝負は最初の1秒。** フックに設計投資の半分を使う。本編が良くてもフックで負けたら見られない
- **検収を機械に組み込む。** 生成→検査→自動リトライ。耳と目の検収は人間、閾値の検査は機械
- **まず1本を最後まで通す。** フック型もキャラ演出も、量産はそのあと
- **飽きさせない単位は「カット」。** 3〜6秒に1回、画面のどこかを変える(カット割り・演出・強調)

## 最初の対話 — 必ず聞くこと

作業を始める前に、ユーザーに以下を確認する:

1. **素材の起点** — 2系統ある:
   - **経路A: 音声がある**(音声配信・ラジオ・収録の切り抜き) → 工程1-A
   - **経路B: テキストだけ**(ブログ・メルマガ・台本) → 工程1-B(TTS)
2. **キャラの有無** — 3択:
   - 自分のキャラ絵がある → キャラリグ(工程2)へ
   - キャラ絵を作りたい → 生成手順を案内(references/character-rig.md 末尾)
   - キャラなしでいい → Bロール+でかタイポ構成(キャラ工程をスキップ)
3. **声の方針**(経路Bのみ) — 自分の声のクローン(fal MiniMax等・有料) / 既製TTS音声 / 録り下ろし
4. **配信先**(Instagram Reels / TikTok / YouTube Shorts)と、**AI音声・AI画像の開示**への同意
5. **fal APIキーの有無**(Bロール画像・TTS利用時に必要)

**声のクローンは、ユーザー本人の声か書面許諾のある声に限る。**
第三者・有名人の声のクローン依頼は断る。AI音声を使う動画には動画内の小表記(`aiVoiceLabel`)とプラットフォームのAI生成ラベルの両方を必ず入れるよう案内する。

## 作業ディレクトリの標準構成

```
short-factory/            # Remotionプロジェクト(npx create-video@latestで作成)
  src/
    CharacterShort.tsx    # 本テンプレート(assets/からコピー)
    Root.tsx              # Composition登録
    cues/                 # 1動画=1ファイル(cues.sample.tsをコピーして作る)
  public/                 # レンダ参照素材(音声・キャラ画像・Bロール・BGM・SE)
  character.json          # キャラ設定(character.template.jsonから作成)
  work/                   # 中間物(書き起こし・カットJSON・QC静止画)。git外
  out/                    # 完成mp4。git外
  assets/                 # 参照音声・voice_id・APIキー(.fal_key)。git外・配布物に混ぜない
```

**APIキー・voice_id・参照音声は assets/ に隔離し、コードに直書きしない。配布・共有物に絶対に混ぜない。**

## 工程0: セットアップ

1. `npx create-video@latest` でRemotionプロジェクトを作成(blankテンプレートでよい)
   - **TypeScriptは5系に固定する**(実測: TypeScript 7はRemotionのバンドラーが必要とする`typescript.sys`を持たず`Cannot read properties of undefined (reading 'readFile')`で落ちる)。公式テンプレートは固定済みだが、手組みするときは`npm i typescript@5`
   - **create-videoは対話プロンプト(TailwindCSS等)に答えられないと進めない**。エージェント実行などの非対話環境でハングしたら手組みに切り替える: package.json(remotion/@remotion/cli/@remotion/media-utils/react/react-dom/typescript@5)+tsconfig(`module: ESNext`+`moduleResolution: bundler`+`jsx: react-jsx`)+src/index.ts(registerRoot)の3点で成立する(実測済み)
2. `CharacterShort.tsx` を src/ へコピーし、Root.tsxにCompositionを登録する:

```tsx
import { Composition } from 'remotion';
import { CharacterShort } from './CharacterShort';
import character from '../character.json';
import { title, cues, scenes } from './cues/my-first-video';

// durationInFramesは「音声実測秒数(ffprobeで測る)+エンドCTAの3秒」×30で決める
// (音声の長さぴったりにするとCTAが映る前に動画が終わる)
<Composition
  id="my-first-video"
  component={CharacterShort}
  durationInFrames={Math.round((50.8 + 3.0) * 30)}
  fps={30}
  width={1080}
  height={1920}
  defaultProps={{ title, audioSrc: 'voice.m4a', character, cues, scenes,
    bgmSrc: 'bgm.m4a', aiVoiceLabel: '声はAIで生成しています' }}
/>
```

3. SEの「ドン」(se-don.wav)をpublic/に用意する。効果音生成AI・フリー音源・ffmpeg合成のどれでもよい(低いキックが1発鳴れば十分)

## 工程1-A: 素材づくり(音声がある場合)

1. **書き起こし**: whisper(turbo・言語明示・segments付き)で全文をタイムコード付きにする
2. **ハイライト選定(人間の仕事)**: 38〜54秒の見どころを選ぶ。清書済みのブログ・記事が既にあるならそれを先に読むと速い。選定基準は「①冒頭がフックになる断言・数字・失敗談 ②単体で意味が通る ③固有名詞の説明が不要」
3. **音声カット(ffmpegの罠・厳守)**:
   - `-ss`/`-to` は必ず `-i` の**前**に置く(後ろだとafadeのstがズレて全編無音化する)
   - 中間カットのafadeは `in 0.06 / out 0.08` の極短(プツ音防止のみ)。最終セグメントだけ `out 0.4`
   - フックを先頭へ移動する構成なら「フック→無音gap→本編」をconcatフィルタで結合
   - 各セグメントは一旦個別に切り出してから結合。出力はaac 48kHz
4. **EQ明瞭化+音圧そろえ**: 工程1-Bの手順5〜6と同じ(EQ→loudnormの順・声トラックのみ)。録音素材はTTSより帯域バランスがばらつくので、EQの効きはかならず耳でA/B確認する

## 工程1-B: 素材づくり(テキストからTTS)

0. **API呼び出しは assets/fal_helpers.py を使う**(TTS/画像/BGMの3サブコマンド入り・キューAPI+ポーリング実装済み。キーは環境変数`FAL_KEY`か`.fal_key`ファイル)。エンドポイントやリクエスト形式を自力で組む必要はない。モデルIDの既定値は実測疎通済み——404になったら https://fal.ai/models で現行IDを確認して`--model`で差し替える
1. **台本化**: 元テキストを45〜60秒(**約280〜370字**。TTSの実測は0.16〜0.17秒/字で、430字級の台本は70秒に膨らむ)の話し言葉に書き直す。構成は「フックの一撃(1文)→本編(3〜5ポイント)→締めの一言」。1文1行
2. **TTSの誤読対策(実測済みの罠)**:
   - **書いたらまず読み事故リント**: `python3 scripts/script_lint.py work/script_XXX.json`(assets/script_lint.pyをコピーして使う)。辞書は2層——①**同字異読(ブロック)**: 「開いた」(あいた/ひらいた)型はTTSがどちらで読んでもASRが同じ漢字に書き戻すため**後段の機械検収では原理的に捕まらない**。約60語を収録 ②**実誤読の実績語(警告)**: 実運用のTTSクローンで実際に事故った語の記録(値下げ→もとげ・体言止め→からだごんどめ 等)。ヒットした語はかな書き/混成表記/言い換えで読みを固定してからTTSに渡す(読みが一意と裁定した語だけ`--accept`)。**耳検収で新種を見つけたら辞書に1行追記して育てる**——この辞書の厚みが品質資産になる
   - **数字は誤読される**(「4億」→「8億」級の事故が実際に起きる)。不安定な数字・英略語は台本側でかな書きに置換する(「よん億円」「ファイア」)
   - 短い間投詞(「あれ?」等)は読み飛ばされる。言い切り文に書き換える
   - 訓読みの動詞も事故る(「下げる」等)。誤読を確認した語だけかな置換する。先回りの全ひらがな化はアクセントを壊すので禁止
3. **機械検収(必須)**: 生成音声をwhisperでASR照合し、**数字は全数一致を機械検算**する。台本と書き起こしの表記ゆれ(漢数字⇄算用数字・お勧め⇄おすすめ)は正規化してから比較する。疑い区間は切り出して0.75倍速で再ASRすると、ASRの誤聴とTTSの実誤読を区別できる。**実装は assets/asr_qc.py をコピーして使う**(全文diff+数字全数照合+リスク語の単独切り出しASRを一発で回す)
4. **ポーズ内クリック検査(必須)**: TTSは読点ポーズの真ん中に舌打ちのような口腔ノイズを吐くことがあり、ASR系ゲートでは原理的に検出できない。**assets/declick_pauses.py で scan→fix する**(検出=静寂の中の短い孤立過渡音・修復=ゼロ化+フェードで尺不変。詳細はreferences/quality-gates.md)。セグメントを再生成するたびに引き直しのガチャがあるので、再生成後は毎回scanする
5. **EQ明瞭化(既定でON・録音/TTS両経路共通)**: loudnormの**前**に、声トラックへ一度だけ通す: `equalizer=f=3000:t=q:w=1:g=3,highshelf=f=6000:g=2,acompressor=threshold=-18dB:ratio=2.5:attack=10:release=120:makeup=3`。低い声・こもる声の聞き取りにくさの正体はピッチではなく**子音の明瞭度**で、3kHz帯を持ち上げると滑舌の輪郭だけが立つ(ピッチ変更はケロるので不採用)。スマホの小型スピーカーで特に効く。掟3つ——**適用は1回だけ**(二重がけは音がキンつく)・**声トラック限定**(BGM/SEにはかけない)・順序は**EQ→loudnorm**(逆だとEQでピークが再び暴れる)
   - **女性声・高めの声はサ行対策チェーンに切り替える**: 標準チェーンの`highshelf=f=6000:g=2`は歯擦音帯域(5〜9kHz)を持ち上げるため、高域成分の多い声だと「サシスセソがうるさい」刺さりが出る(実測でサ行ピーク+4.5dB)。女性声はシェルフ半減+ディエッサーの派生形を使う: `equalizer=f=3000:t=q:w=1:g=3,highshelf=f=6000:g=1,deesser=i=0.3,acompressor=threshold=-18dB:ratio=2.5:attack=10:release=120:makeup=3`。deesserはサ行が鳴った瞬間だけ動的に高域を抑えるので、3kHzの明瞭化はそのまま・こもらずにうるささだけ取れる。それでも刺さる声は`deesser=i=0.5`まで上げる(高域全体がやや暗くなるので耳でA/B確認)。判定は肩書きでなく耳——男性でも歯擦音が強い声なら切り替える
6. 音声はloudnorm(I=-16目安)で音圧をそろえてからpublic/へ置く。**loudnormの後はdeclick_pauses.pyをもう一度scanする**(ゲイン増幅で閾値未満だったクリックが新出する・実測。EQ→loudnormと通した後も同じ)

## 工程2: キャラリグ

references/character-rig.md の手順で、キャラ画像の分解(胴体/頭)と座標計測(口・目・首の付け根)を行い、character.json を作る。**計測はClaudeが画像を読んで行う**(ユーザーに座標を測らせない)。キャラなし構成の場合はこの工程をスキップし、scenesをbroll/still/typoだけで組む。

## 工程3: フック設計

references/hook-styles.md の5型(キーアート/動画先行/巨大数字/対比2分割/漫画コマ)から、**素材の意味で選ぶ**(金額の話なら巨大数字、ビフォーアフターなら対比、あるあるなら漫画)。**直近2本と同じ型を使わない**。

## 工程4: cues/scenes執筆(人間の言葉のセンスを使う工程)

assets/cues.sample.ts をコピーして書く。機械化しない——ここが動画の質の本体。

- **字幕の掟**: 読点「、」は全廃。間は改行と「|」で作る。1画面2行まで
- **強調`**語**`**はアクセント1色のみ・言い切りの核だけに使う
- **どどど演出「|」は入れすぎない**(目安: 19cueに7個。フック・タイポ・パンチラインだけ)
- **本編のでか文字カード(typo)は`bg`を必ず指定する**(bgなしの素の暗背景は「背景が入っていない」ように見える。断言=shu/速度=mono/告白・文化=washi。未指定は安全網でmonoに落ちる)
- **カット割り**: avatar(キャラ)/broll(生成映像)/still(静止画Ken Burns)/typo(でか文字)を3〜6秒間隔で切り替える。同じtypeを3連続させない
- moodとgesture(nod/point/open)は声のトーンに合わせる。全cueに付けない(うるさくなる)
- **表情は7種**(すべてコード描画・素材追加不要): `smile`(にっこり)/`laugh`(大笑い)/`stern`(気難しい=眉ひそめ+半目+への字)/`sad`(悲しい=八の字眉+への字)/`serious`(真顔=直線口+フラット眉)/`wink`(ウインク)/無指定=normal。使い分け——決意・断言=serious、苦言・怒り=stern、損・後悔=sad、オチ・軽口=smile/laugh/wink
- **表情は「にこにこ一辺倒」にしない**: シリアス・怒り・苦い話の行(「見過ごせない」「赤字」「失敗」等)に笑顔を当てると内容とチグハグになる(実FB)。**山(smile/laugh)と谷(stern/sad)と地面(serious)を1本の中に配役する**のが完成形
- **moodはキャラが映るカット(avatar)のcueに付ける**(実測の配役ミス): still/broll/typoカット中のcueにmoodを付けても顔が映らないので無効。cuesとscenesを突き合わせて、表情を見せたい行がavatar区間に乗っているか確認する

## 工程5: Bロール・決め絵の生成(任意)

- **静止画**: 画像生成AI(fal GPT Image系等)で生成 → **1枚ずつ目視検収**(生成画像は「それっぽい嘘の日本語」や意図しない顔を混ぜる。人物は後ろ姿・顔なしを明示指定すると安定)。呼び出しは`python3 assets/fal_helpers.py image "<prompt>" out.png --size portrait_16_9`(sizeはプリセット名のみ・ピクセル指定は422エラー)
- **動画化**: image-to-video(Seedance等)は**480pで生成し、ローカルアップスケール**(Real-ESRGAN等)で仕上げる。高解像度課金より速くて安い
- 静止画のままKen Burns(`type:'still'` + kb)で動かすのが最安。動画化が要らない場面はこちら
- 実測コスト目安: TTS数円/本・Bロール静止画10円弱/枚・**1本あたり合計50円前後**(リテイク込み)

## 工程6: レンダと検収

0. **型検査**: `npx tsc --noEmit` を先に通す(cuesのプロパティ打ち間違いをレンダ前に捕まえる最安の門)
1. **静止画QC**: `npx remotion still <id> --frame <N>` でフック頭・カット切替・**本編のでか文字カード**・CTAの各フレームを撮り、構図・字幕位置・背景・セーフゾーンを目視確認
2. **本番レンダ**: `npx remotion render <id> out/<id>.mp4`(1080x1920/H.264/AAC)
3. **機械検収**: references/quality-gates.md の閾値表を全部通す(長さ・音声・字幕・セーフゾーン)
4. **口パクのキャリブレーション**: 最初の1本では、無音区間で口が開く/発話中に閉じるようなら CharacterShort.tsx の口パク閾値(rms 0.006/0.11)を素材の実測RMSに合わせて調整する

## 工程7: 公開

- **AI開示**: 動画内小表記(`aiVoiceLabel`)+各プラットフォームのAI生成コンテンツラベルの両方。TikTokはAI生成表示ON、Instagram/YouTubeも該当設定を有効にする
- **法令チェック**: references/quality-gates.md §リーガル検品。**効果・利益の断定表現は音声ごと言い換える**(字幕だけ直して音声に残すのは監査逃れであり禁止)
- 各プラットフォームへの自動投稿APIは規約が頻繁に変わるため、このスキルでは完成動画+キャプション案の「投稿パック」までを成果物とし、投稿はユーザーの手で行うことを既定とする

## 量産化と運用の掟

1本目が通ったら量産に入る。運用で効くのは:

- **フック型の輪番**: 直近2本と同じ型・同じ決め絵を使わない(マンネリの正体は「1変数以外の全固定」)
- **Bロールは都度生成**: 使い回しはマンネリの温床。1本ごとに数枚生成して差し替える
- 週2〜3本の定時投稿をまず4週間続けてから、伸びたフック型に寄せる
- cuesファイルは1動画1ファイルで積み上げる(過去作が次の台本の型見本になる)

## 出荷前チェックリスト(全項目必須)

references/quality-gates.md の総合検収12項目を実行する。
特に: **参照音声・APIキー・voice_idが共有物に混ざっていないこと**を、共有前にフォルダの全ファイル列挙で確認する。
